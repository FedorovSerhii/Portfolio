# Результаты локальной проверки Portfolio

Этот отчёт описывает этап от 10 октября 2026 года. Последующее обновление главной и контактов проверено отдельно: [growth-validation.md](growth-validation.md).

Работа подготовлена в `codex-portfolio-navigation` поверх изменений PR #6. Локальный HEAD и сохранённая ссылка `origin/codex-portfolio-navigation` остаются на `b4eead89fbfcc16391f4415b0551559872304600`. Новые изменения находятся в рабочей директории; коммитов, push, merge и публикации в этой задаче не было. Для реализации использована Astra с уровнем рассуждения `max`.

## Что реализовано

- В украинском разделе «Освіта» добавлен `h1`. Рендеринг всех разделов обеспечивает непустой заголовок `section-title`, на который ссылается `main`.
- Сохранены имя Сергея Фёдорова и существующие email, Telegram и LinkedIn. Новые навыки, услуги, профиль и интерфейс демонстрации доступны на английском, русском, украинском и польском.
- Добавлены n8n, ChatGPT/Codex, работа с моделями и агентными системами. В новые сведения не добавлены работодатели, стаж, сертификаты, результаты, цены или обещания дежурства. Cloud Code и Claude Code не добавлены.
- Услуги резервного копирования с проверкой восстановления, мониторинга Grafana с уведомлениями и сопровождения Linux/Docker разделены на разовую настройку и ежемесячное обслуживание. Две кнопки ведут в соответствующие режимы помощника.
- Статусы поиска работы и доступности для заказов настраиваются в `portfolio-data.js`. Публикация требует `confirmed: true` и разрешённого значения; текущие неподтверждённые статусы скрыты.
- `profile.json`, `profile.md`, `llms.txt`, видимый профиль и JSON-LD Person используют общие факты. JSON-LD обновляется при выборе языка; публичные файлы не содержат скрытых инструкций агентам.
- Чат явно обозначен как локальная демонстрация с готовыми ответами. Он не подключён к модели, n8n или Telegram. История и черновики существуют только в памяти страницы. Очевидные email, телефоны и контактные имена отклоняются при отправке сообщения или просмотре предложения.
- Просмотр предложения показывает точный текст; согласие изначально снято и сбрасывается при правках или смене темы. Реальная отправка всегда отключена. Персонаж имеет конечную прогулку, прыжок, переключатель анимации и поддержку reduced motion.

Команды для повторения и требования к инструментам находятся в [tests/README.md](../tests/README.md). Основные команды:

```bash
npm run check:profile
node --test --test-isolation=none tests/profile.test.mjs tests/adapter.test.mjs
node tests/navigation.cjs
node tests/demo-browser.cjs
```

Для последних двух команд нужны локальный HTTP-сервер, Playwright и Chromium. В этой среде использовались существующие установки через `PLAYWRIGHT_MODULE_PATH` и `PLAYWRIGHT_BROWSERS_PATH`; инструменты не являются зависимостями сайта.

Визуально просмотрены снимки услуг и помощника на настольном и мобильном экранах. Карточки и кнопки помещаются в ширину; персонаж находится в отдельной области и не перекрывает текст или управление. Снимки сохранены отдельно от исходников в `/workspace/scratch/portfolio-review/`.

## Что ждёт подключения n8n

Реализован только отключённый клиентский адаптер будущих same-origin `/api/assistant` и `/api/proposals`. Ошибки и успешные ответы адаптера проверены локальными подставными ответами, без обращения к внешним сервисам.

Серверный relay, workflow n8n, реальная модель, Telegram-доставка, серверные секреты, аутентификация, CSRF, rate limits, контроль бюджета, серверная привязка согласия к проверенному тексту и идемпотентность ещё не реализованы и не проверены в работающей интеграции. Требования описаны в [backend-integration.md](backend-integration.md). GitHub Pages сам по себе не предоставляет эти серверные маршруты.

Проверки выполнены в Chromium и не являются полной сертификацией доступности или проверкой всех браузеров и программ экранного доступа.
